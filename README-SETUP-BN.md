# জনতার কথা — সেটআপ গাইড (বাংলা)

এই প্রজেক্টটি **Next.js 15 + TypeScript + Tailwind CSS** দিয়ে তৈরি — অর্থাৎ React অ্যাপ,
সরাসরি Vercel-এ পাবলিশ করা যাবে। ব্যাকএন্ড হিসেবে **Supabase** (PostgreSQL) ব্যবহার করা হয়েছে।

> ⚠️ Supabase ছাড়াও অ্যাপটি চলবে — তখন হার্ডকোড করা ডেমো ডেটা দেখাবে।
> কিন্তু রিপোর্ট/এলার্ট সংরক্ষণ করতে হলে Supabase সেটআপ করতেই হবে।

> 🚀 **সহজ উপায় (সব একসাথে):** `supabase/SCHEMA-ALL.sql` — ১৩টা ধাপের সব SQL
> এক ফাইলে সাজানো আছে। Supabase Dashboard → **SQL Editor** → **New Query** →
> পুরো ফাইল পেস্ট → **Run** — একবারেই সব টেবিল + RLS + সিড ডেটা তৈরি।
> (নিচে ধাপ ১-এ আলাদা ফাইলের তালিকাও রাখা আছে, দরকার হলে।)

> 💰 **খরচ:** Vercel ফ্রি প্ল্যান + Supabase ফ্রি প্ল্যান + নিজের ডোমেইন
> (~৳১২০০–১৫০০/বছর) — এতেই চলবে। শেয়ার্ড/cPanel হোস্টিং লাগবে না।
> Supabase ফ্রি প্রজেক্ট ৭ দিন অব্যবহৃত থাকলে pause হয় (এক ক্লিকে resume);
> বিরক্ত লাগলে পরে $25/মাস Pro নেওয়া যায়।

## ধাপ ১ — Supabase প্রজেক্ট বানান

1. [supabase.com](https://supabase.com) → **New Project** বানান
2. প্রজেক্ট খুলে বাম মেনু → **SQL Editor** → **New Query**
3. এই রিপোর `supabase/schema.sql` ফাইলের **পুরো লেখা** কপি করে পেস্ট করুন → **Run** চাপুন
   - ১২টা টেবিল + RLS পলিসি + `evidence` স্টোরেজ বাকেট + সিড ডেটা তৈরি হয়ে যাবে
4. তারপর **আরেকটা New Query** খুলে `supabase/schema-v2-locations.sql` চালান (Phase 2)
   - লোকেশন হায়ারার্কি টেবিল (বিভাগ/জেলা/উপজেলা/থানা/ইউনিয়ন) + রিপোর্টে লোকেশন
     কলাম ও `media_urls` + পাবলিক `media` স্টোরেজ বাকেট (ছবি/ভিডিও আপলোডের জন্য)
   - সিড: সব ৮টি বিভাগ, ময়মনসিংহ বিভাগের ৪ জেলা, ময়মনসিংহ জেলার ১৩ উপজেলা,
     ময়মনসিংহ সদরের কোতোয়ালী মডেল থানা ও বর্তমান ১২টি ইউনিয়ন
5. তারপর **আরেকটা New Query**-তে `supabase/schema-v3-members-surveys.sql` চালান (Phase 3)
   - `members` (সদস্য নিবন্ধন), `surveys` (এলাকার জরিপ) ও `survey_responses`
     (ভোট) টেবিল তৈরি হবে
   - ⚠️ এই ফাইল না চালালে নিবন্ধন/জরিপ ডেমো মোডে চলবে (ডেটা স্থায়ী হবে না)
6. তারপর **আরেকটা New Query**-তে `supabase/schema-v4-roads.sql` চালান (Phase 4)
   - `roads` (এলাকাভিত্তিক রোড) ও `road_updates` (লাইভ আপডেট) টেবিল তৈরি হবে
   - সিড: ময়মনসিংহ সদরের ৫টি রোড ও তাদের সাম্প্রতিক আপডেট
   - ⚠️ এই ফাইল না চালালে রোডের অবস্থা ডেমো মোডে চলবে (ডেটা স্থায়ী হবে না)
7. তারপর **আরেকটা New Query**-তে `supabase/schema-v5-spots.sql` চালান (Phase 5)
   - `roads` টেবিলে `kind` (রোড/গুরুত্বপূর্ণ স্থান) ও `locality_name` (এলাকার নাম)
     কলাম, `road_updates`-এ `preset_key` কলাম এবং নতুন ৯টি স্ট্যাটাস যোগ হবে
   - সিড: ময়মনসিংহ সদরের ৬টি গুরুত্বপূর্ণ মোড়/স্থান ও তাদের সাম্প্রতিক আপডেট
   - ⚠️ এই ফাইল না চালালে মোড়/স্থান ও এক-ক্লিক আপডেট ডেমো মোডে চলবে

8. সবশেষে **আরেকটা New Query**-তে `supabase/schema-v6-live-shares.sql` চালান (Phase 6)
   - নতুন `live_shares` টেবিল তৈরি হবে — SOS পেজের লাইভ লোকেশন শেয়ারের জন্য
   - ⚠️ এই ফাইল না চালালে লাইভ শেয়ার ডেমো মোডে (মেমরিতে) চলবে

> 📍 **ধাপে ধাপে লোকেশন ডেটা:** বাকি জেলা/উপজেলা/থানা/ইউনিয়নের তথ্য ধাপে ধাপে
> যোগ হবে — অ্যাডমিন প্যানেলের **লোকেশন** ট্যাব থেকে (বিভাগ → জেলা → উপজেলা →
> থানা/ইউনিয়ন) অথবা নতুন seed SQL ফাইল দিয়ে। গঠন (schema) পুরো বাংলাদেশের
> জন্য তৈরি; Phase 1-এ শুধু ময়মনসিংহের ডেটা দেওয়া হয়েছে।

## ধাপ ১.৫ — সদস্য, জরিপ ও "আমার এলাকার মানুষ" (Phase 3)

- **নিবন্ধন (`/register`)** — নাম + মোবাইল নম্বর + নিজ এলাকা (স্থায়ী) + বর্তমান
  এলাকা দিয়ে সদস্য হওয়া যায়। পরিচয় = ফোন নম্বর (OTP নেই); পরে একই নম্বর
  দিয়ে আবার প্রবেশ করা যায়। ফোন নম্বর **কখনো** অন্য সদস্য/পাবলিককে দেখানো
  হয় না — শুধু অ্যাডমিন প্যানেলের **সদস্য** ট্যাবে দেখা যায়।
- **জরিপ (`/surveys`)** — অ্যাডমিন **জরিপ** ট্যাব থেকে প্রশ্ন + ২–৬টি অপশন +
  এলাকা-পরিধি (সারা দেশ / বিভাগ / জেলা / উপজেলা / থানা / ইউনিয়ন) দিয়ে জরিপ
  তৈরি করেন। যেসব সদস্যের **নিজ এলাকা** ওই পরিধির মধ্যে, শুধু তারাই ভোট দিতে
  পারেন — প্রতিজন একবার। ভোটের পর ফলাফল (% বার) দেখা যায়। অ্যাডমিন ফলাফলে
  **থানাভিত্তিক ও ইউনিয়নভিত্তিক** বিভাজনও দেখতে পান।
- **আমার এলাকার মানুষ (`/amar-elaka`)** — সদস্যদের নিজ এলাকা বনাম বর্তমান
  এলাকা মিলিয়ে **স্বয়ংক্রিয়** হিসাব: মোট সদস্য, কজন নিজ এলাকায়, কজন অন্য
  এলাকায় আছেন + নামের তালিকা (শুধু যারা "দেখান" চালু রেখেছেন)।
  ⚠️ বর্তমান এলাকা = সদস্যের **নিজের দেওয়া** তথ্য (প্রোফাইল থেকে বদলানো
  যায়) — এটি GPS লোকেশন **নয়**।
- **ধাপে ধাপে চালু:** প্রথমে ময়মনসিংহ সদর দিয়ে শুরু করুন — সেখানকার সদস্যরা
  নিবন্ধন করলে জরিপ ও "আমার এলাকার মানুষ" সক্রিয় হয়ে যাবে। নতুন এলাকার
  ডেটা (লোকেশন ট্যাব) যোগ হলেই সেই এলাকার মানুষও একই সুবিধা পাবেন।

## ধাপ ১.৭ — এলাকাভিত্তিক রোডের অবস্থা (Phase 4)

- **রোডের অবস্থা (হোম সেকশন + `/roads`)** — হোম পেজে আলাদা সেকশনে এলাকা
  (বিভাগ → জেলা → উপজেলা → থানা → ইউনিয়ন) বেছে সেই এলাকার রোডগুলোর বর্তমান
  অবস্থা দেখা যায়: ভালো / মোটামুটি / ভাঙা-ঝুঁকিপূর্ণ / মেরামত চলছে / যানজট /
  জলাবদ্ধ / বন্ধ — রঙিন ব্যাজসহ, সাথে স্ট্যাটাসভিত্তিক সারসংক্ষেপ।
- **লাইভ আপডেট** — প্রতিটি রোডের বর্তমান অবস্থা = তার **সর্বশেষ আপডেট**।
  যে কেউ রোডের পেজে গিয়ে (`/roads/[id]`) নতুন অবস্থা + বিবরণ + চাইলে ছবি দিয়ে
  আপডেট দিতে পারেন; আগের সব আপডেট টাইমলাইনে থেকে যায়।
- **অ্যাডমিন** — **রোড** ট্যাব থেকে নতুন রোড যোগ/এডিট/মুছে ফেলা এবং যেকোনো
  আপডেট মুছে (মডারেশন) করা যায়। নতুন এলাকার রোড সেভাবেই ধাপে ধাপে যোগ করুন।

## ধাপ ১.৯ — গুরুত্বপূর্ণ স্থান (মোড়) ও এক-ক্লিক কুইক আপডেট (Phase 5)

- **মোড় ও গুরুত্বপূর্ণ স্থান** — রোডের পাশাপাশি এখন গুরুত্বপূর্ণ মোড়/স্থানেরও
  (যেমন: চরপাড়া মোড়, নতুন বাজার, জিলা স্কুল মোড়) লাইভ অবস্থা দেখা যায়।
  হোমের "রোডের অবস্থা" সেকশন ও `/roads` পেজে **[রোডসমূহ | মোড় ও স্থান]**
  টগল দিয়ে দুটোর মধ্যে বদলানো যায়। স্থানের সাথে ঐচ্ছিক **এলাকার নাম**
  (locality) থাকে — ইউনিয়ন → এলাকা অনুযায়ী সাজানো।
- **এক-ক্লিক কুইক আপডেট** — তৈরি-করা (preset) আপডেটে শুধু **একবার ট্যাপ**
  করলেই পোস্ট হয়ে যায়, কিছু লিখতে হয় না: জ্যাম বেশি / হালকা জ্যাম /
  জ্যাম নেই, ঝামেলা চলতেছে, দুর্ঘটনা, রাস্তা বন্ধ, এখন বিদ্যুৎ নাই /
  বিদ্যুৎ এসেছে, গ্যাস নাই / এসেছে, পানি নাই / এসেছে, রাস্তা ভাঙা,
  মেরামত চলছে, জলাবদ্ধ, পানি নেমে গেছে, সব স্বাভাবিক। কার্ডে ছোট chip-সারি
  থাকে; ডিটেইল পেজে গ্রুপ অনুযায়ী পুরো প্যানেল + চাইলে লিখে কাস্টম
  আপডেটও দেওয়া যায় (আগের মতোই)।
- স্ট্যাটাস এখন মোট ১৬টি (আগের ৭টি + নতুন ৯টি) — সব জায়গায় (ব্যাজ, chip,
  টাইমলাইন) একই রঙ/নাম ব্যবহৃত হয়।
- **অ্যাডমিন** — **রোড** ট্যাবে এখন ধরন (রোড / গুরুত্বপূর্ণ স্থান) বেছে
  এলাকার নামসহ স্থান যোগ করা যায়।

## ধাপ ১.১০ — SOS লাইভ লোকেশন শেয়ার (Phase 6)

- **লাইভ শেয়ার (SOS পেজ)** — SOS পেজের একদম উপরে নতুন প্যানেল: উদ্দেশ্য বেছে
  (🚨 বিপদে আছি / 🩸 রক্ত দরকার / 🤝 সাহায্য দরকার / সাধারণ) **এক ট্যাপে**
  লাইভ লোকেশন শেয়ার শুরু হয়। ফোনের GPS থেকে অবস্থান নিয়ে একটি পাবলিক
  লিংক (`/live/…`) তৈরি হয় — লিংকটি কপি করে বা WhatsApp/SMS দিয়ে পাঠিয়ে
  দিলে যে কেউ লাইভ ম্যাপে (OpenStreetMap) শেয়ারকারীর অবস্থান দেখতে পাবেন,
  চাইলে Google Maps-এও খুলতে পারবেন।
- **মেয়াদ ও নিরাপত্তা** — শেয়ার **১ ঘণ্টা** পর নিজে থেকে বন্ধ হয়ে যায়;
  শেয়ারকারী যেকোনো সময় নিজে বন্ধ করতে পারেন। ফোন নম্বর শুধুমাত্র
  শেয়ারকারী চাইলে (টগল) পাবলিক দেখায়। শেয়ার বন্ধ/আপডেট শুধু শেয়ারকারীর
  নিজের ডিভাইস থেকেই করা যায় (owner token)।
- **রক্ত দরকার** বেছে শেয়ার করলে তা **রক্ত পেজে** "লাইভ রক্তের প্রয়োজন"
  স্ট্রিপে দেখায় (গ্রুপসহ), যাতে দাতারা দ্রুত সাড়া দিতে পারেন।
- **বিপদে আছি** শেয়ার শুরু হলে অ্যাডমিনের **SOS ইনবক্সেও** একটি অ্যালার্ট
  যায়; অ্যাডমিন সব লাইভ শেয়ার সেখান থেকে দেখতে ও প্রয়োজনে বন্ধ করতে পারেন।
- ⚠️ **ওয়েবের সীমাবদ্ধতা:** শেয়ারকারীর ব্রাউজার/ট্যাব খোলা থাকলেই লোকেশন
  লাইভ আপডেট হয় (স্ক্রিন জেগে রাখার চেষ্টা করা হয়)। ট্যাব বন্ধ করলে শেষ
  অবস্থানটাই ম্যাপে থেকে যায় — ব্যাকগ্রাউন্ড ট্র্যাকিংয়ের জন্য native app
  লাগবে, নিজস্ব ডোমেইন দিলেও ওয়েবে তা সম্ভব নয়।

## ধাপ ১.১১ — পুশ নোটিফিকেশন (Phase 8)

Supabase SQL Editor-এ `supabase/schema-v8-push.sql` চালান (আগেরগুলোর পরে)।

- **ইন-অ্যাপ নোটিফিকেশন কেন্দ্র** — হেডারের 🔔 বেলে অপঠিত সংখ্যার ব্যাজ,
  `/notifications` পেজে সব আপডেটের তালিকা ("সব পড়া হয়েছে" বাটনসহ)।
- **ব্রাউজার পুশ** — প্রোফাইল পেজে "পুশ নোটিফিকেশন" টগল: ব্রাউজার অনুমতি →
  সাবস্ক্রিপশন সংরক্ষণ। ফোনে সরাসরি পুশ আসে, ট্যাপ করলে সংশ্লিষ্ট পেজ খোলে।
- **অ্যাডমিন টেস্ট** — অ্যাডমিন প্যানেলের **নোটিফিকেশন** ট্যাবে শিরোনাম +
  বার্তা লিখে সবাইকে পাঠান; ফলাফল সৎভাবে দেখায় (পুশ সফল/ব্যর্থ/ইন-অ্যাপ)।

**ব্রাউজার পুশের জন্য VAPID কী (ঐচ্ছিক কিন্তু পুশের জন্য আবশ্যক):**

```bash
npx web-push generate-vapid-keys
```

যে দুটি কী পাবেন, সেগুলো Vercel → Project → **Settings → Environment
Variables**-এ বসান (Production):

- `VAPID_PUBLIC_KEY` = Public Key
- `VAPID_PRIVATE_KEY` = Private Key
- `VAPID_SUBJECT` = `mailto:আপনার-ইমেইল@example.com`

> 💡 VAPID কী না বসালেও সব কাজ করে — শুধু `POST /api/push/send` তখন
> ইন-অ্যাপ কেন্দ্রে লিখে এবং সৎভাবে `{ delivered: "inapp",
> reason: "no-vapid-keys" }` রিটার্ন করে। মিথ্যা "পাঠানো হয়েছে" কখনো দেখায় না।

## ধাপ ১.১২ — বিশ্বস্ত পরিচিতজন (Phase 11)

Supabase SQL Editor-এ `supabase/schema-v11-contacts.sql` চালান (আগের সব ফাইলের পরে;
Phase 9/10-এর ফাইল থাকলে সেগুলোর পরেই)।

- **আমার পরিচিতজন** — প্রোফাইল পেজে লগইন করা সদস্যরা নাম + মোবাইল
  (01XXXXXXXXX) দিয়ে পরিচিতজন যোগ/মুছে ফেলতে পারেন।
- **SOS-এ এক-ট্যাপ অ্যালার্ট** — লাইভ শেয়ার চালু থাকলে \"পরিচিতদের জানাও\"
  প্যানেলে প্রতিটি পরিচিতজনের জন্য WhatsApp বোতাম (প্রিফিলড বাংলা SOS
  বার্তা + লাইভ লিংকসহ) ও লিংক-কপি বোতাম।
- 🔒 **গোপনীয়তা:** তালিকা শুধু মালিক সদস্য ও অ্যাডমিন দেখতে পান — লগআউট
  অবস্থায় API 401 দেয়। অ্যাডমিন রিড `GET /api/admin/contacts` থেকে।
- ⚠️ **ওয়েবের সীমাবদ্ধতা:** ওয়েব নিজে SMS পাঠাতে পারে না — অ্যালার্ট হয়
  WhatsApp ডিপ-লিংক + কপি-লিংক দিয়ে; \"SMS পাঠানো হয়েছে\"-এর মতো মিথ্যা
  দাবি UI-তে কোথাও নেই।
- পরিচিতজনের নম্বরটি কোনো নিবন্ধিত সদস্যের হলে, শেয়ার শুরুর সময় Phase 8-এর
  ইন-অ্যাপ কেন্দ্রেও একটি SOS নোটিফিকেশন লেখা হয় (বেস্ট-এফোর্ট; কেন্দ্রটি
  গ্লোবাল ফিড হওয়ায় এটি সবার কাছে দৃশ্যমান — ব্যক্তিগত অ্যালার্ট নয়)।

## ধাপ ১.১৩ — ফোন/ইমেইল রেজিস্ট্রেশন + OTP যাচাইকরণ (Phase 13)

Supabase SQL Editor-এ `supabase/schema-v13-auth.sql` চালান (আগের সব ফাইলের পরে)।

- **নিবন্ধন ২-ধাপে** — `/register` পেজে নাম + মোবাইল নম্বর/ইমেইল → "কোড পাঠাও" → ৬ সংখ্যার OTP (৫ মিনিট মেয়াদ, ৬০ সেকেন্ড রিসেন্ড কুলডাউন, সর্বোচ্চ ৫ বার ভুল চেষ্টা) → যাচাই।
- **কোনো পাসওয়ার্ড নেই** — পুরো সিস্টেম OTP-ভিত্তিক। ফোন যাচাই হলে অ্যাকাউন্ট ✅ ভেরিফাইড; শুধু ইমেইল যাচাই হলে ⏳ আনভেরিফাইড থাকে — ফোন যাচাই না হওয়া পর্যন্ত ভেরিফাইড হয় না। প্রোফাইলে স্ট্যাটাস চিপ + ইমেইল-শুধু অ্যাকাউন্টের জন্য "ফোন যোগ করো" বাটন।
- **পুরনো সদস্যরা** (আগের ফোন-সেশন) আগের মতোই কাজ করবে — তবে OTP দিয়ে যাচাই না করা পর্যন্ত আনভেরিফাইড হিসেবে দেখাবে।

**বাস্তব SMS/ইমেইলের জন্য (ঐচ্ছিক — না দিলেও সব কাজ করে):**

বাংলাদেশে বাস্তব SMS পাঠাতে একটি **পেইড SMS গেটওয়ে** লাগবে (যেমন SSL
Wireless / D7 Networks / Twilio)। গেটওয়ে অ্যাকাউন্ট খুলে API ক্রেডেনশিয়াল
সংগ্রহ করুন, তারপর Vercel → Project → **Settings → Environment
Variables**-এ (Production) বসান:

- `SMS_API_URL` = গেটওয়ের HTTP API ঠিকানা (POST JSON `{to, message}` — গেটওয়ের ডক অনুযায়ী)
- `SMS_API_KEY` = API কী/টোকেন
- `SMS_API_SENDER` = (ঐচ্ছিক) প্রেরকের নাম/নম্বর

ইমেইলে OTP পাঠাতে SMTP বসান:

- `SMTP_HOST`, `SMTP_PORT` (সাধারণত 587), `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`

> 💡 SMS/SMTP না বসালেও সব কাজ করে — তখন OTP কোডটি ডেমো ব্যানারে দেখায়
> ("ডেমো মোড: কোড 123456") এবং সার্ভার কনসোলে লগ হয়। UI কখনো মিথ্যা
> "SMS পাঠানো হয়েছে" দাবি করে না — বাস্তব পাঠানো কেবল তখনই দেখায় যখন
> প্রোভাইডার কনফিগার করা থাকে এবং তার কল সফল হয়।

- **প্রোফাইল** — মোট পয়েন্ট, ব্যাজ শেলফ, দুটি আলাদা তালিকা "➕ অর্জিত
  পয়েন্ট" ও "➖ কাটা পয়েন্ট", এবং "শীর্ষ অবদানকারী" তালিকায় দেখানোর
  opt-in টগল।
- **শীর্ষ অবদানকারী** — হোমপেজের রেল সেকশন + `/api/leaderboard`।

## ফিচার তালিকা (বর্তমান)

1. **হোম ফিড** — রিপোর্ট কার্ড + ক্যাটাগরি ফিল্টার + জরুরি কল স্ট্রিপ + ভ্রমণ মোড টিজার
2. **সমস্যা জানান** — রিপোর্ট ফর্ম (বেনামী টগল, প্রমাণ লকার অপশন, এলাকা নির্বাচন, ছবি/ভিডিও সংযুক্তি)
3. **জরুরি SOS** — ৯৯৯/১০৯/৩৩৩ এক-ট্যাপ কল, ৫০ জনে এলার্ট, নীরব SOS সেটআপ, ভুয়া কল স্ক্রিন
4. **ভ্রমণ মোড** — যাচাইকৃত গাইড + নিরাপদ আশ্রয়
5. **লাইভ ম্যাপ** — ঘটনা মার্কার + নিরাপদ রুট + এলাকা রেটিং ভোট
6. **পরিবার ট্র্যাকিং** — সদস্যদের অবস্থা কার্ড
7. **প্রমাণ লকার** — এনক্রিপ্টেড প্রমাণ তালিকা
8. **রক্তদাতা** — সক্রিয় দাতা + রক্তের অনুরোধ
9. **সমাধান ট্র্যাকার** — পৌরসভার আপডেট (হোমে)
10. **স্বেচ্ছাসেবক লিডারবোর্ড** (হোমে)
11. **সম্পূর্ণ রেসপন্সিভ (Phase 2)** — মোবাইলে আগের মোবাইল ভিউ; ডেস্কটপে সাইডবার
    নেভিগেশন + প্রশস্ত মাল্টি-কলাম লেআউট (হোমে ডান রেল, ম্যাপে পাশের প্যানেল)
12. **লোকেশন হায়ারার্কি (Phase 2)** — বিভাগ → জেলা → উপজেলা → থানা → ইউনিয়ন;
    রিপোর্ট ফর্মে ক্যাসকেডিং সিলেক্টর, কার্ডে এলাকা-ক্রম (ব্রেডক্রাম্ব)
13. **ছবি/ভিডিও আপলোড (Phase 2)** — রিপোর্টে সর্বোচ্চ ৪টি মিডিয়া (Supabase
    Storage `media` বাকেট); Supabase ছাড়া ডেমো মোডে লোকাল প্রিভিউ
14. **সদস্য নিবন্ধন (Phase 3) + OTP যাচাইকরণ (Phase 13)** — নাম + ফোন/ইমেইল,
    ৬ সংখ্যার OTP (পাসওয়ার্ড নেই); ফোন যাচাই → ✅ ভেরিফাইড, শুধু ইমেইল →
    ⏳ আনভেরিফাইড; প্রোফাইলে বর্তমান এলাকা বদলানো ও দৃশ্যমানতা টগল; ফোন
    নম্বর সম্পূর্ণ ব্যক্তিগত
15. **এলাকার জরিপ (Phase 3)** — এলাকাভিত্তিক জরিপ, নিজ এলাকার সদস্যদের
    একবার ভোট, ফলাফল বার; অ্যাডমিনে থানা/ইউনিয়নভিত্তিক বিভাজন
16. **আমার এলাকার মানুষ (Phase 3)** — নিজ এলাকার সদস্যদের স্বয়ংক্রিয়
    হিসাব (কে নিজ এলাকায়, কে অন্য এলাকায়); বর্তমান এলাকা স্ব-ঘোষিত, GPS নয়
17. **এলাকাভিত্তিক রোডের অবস্থা (Phase 4)** — হোমে আলাদা সেকশন + `/roads`;
    এলাকা ফিল্টারে রোডের বর্তমান অবস্থা (৭টি স্ট্যাটাস), নাগরিকদের লাইভ
    আপডেট (ছবিসহ) ও টাইমলাইন; অ্যাডমিনে রোড ব্যবস্থাপনা ও মডারেশন
18. **গুরুত্বপূর্ণ স্থান/মোড় + এক-ক্লিক আপডেট (Phase 5)** — মোড় ও গুরুত্বপূর্ণ
    স্থানের লাইভ অবস্থা (এলাকার নামসহ), [রোডসমূহ | মোড় ও স্থান] টগল;
    তৈরি preset-এ এক ট্যাপেই আপডেট (জ্যাম, ঝামেলা, বিদ্যুৎ/গ্যাস/পানি ইত্যাদি);
    স্ট্যাটাস মোট ১৬টি
19. **SOS লাইভ লোকেশন শেয়ার (Phase 6)** — SOS পেজ থেকে উদ্দেশ্য বেছে
    (বিপদ / রক্ত / সাহায্য / সাধারণ) এক ট্যাপে GPS লাইভ-লিংক (`/live/…`);
    লিংকপ্রাপ্তরা ম্যাপে লাইভ অবস্থান দেখেন; ১ ঘণ্টায় মেয়াদ শেষ, নিজে বন্ধও
    করা যায়; রক্তের শেয়ার রক্ত পেজে লাইভ স্ট্রিপে, বিপদের শেয়ার অ্যাডমিন
    SOS ইনবক্সে যায়
20. **পুশ নোটিফিকেশন (Phase 8)** — VAPID ওয়েব-পুশ (প্রোফাইলে টগল) +
    ইন-অ্যাপ নোটিফিকেশন কেন্দ্র (হেডারে 🔔 বেল + ব্যাজ, `/notifications`);
    অ্যাডমিনে টেস্ট নোটিফিকেশন; VAPID কী না থাকলে সৎভাবে শুধু ইন-অ্যাপে যায়

## লোকাল ডেভেলপমেন্ট

```bash
npm install
cp .env.example .env.local   # মানগুলো বসান
npm run dev                   # http://localhost:3000
```

যাচাই:
```bash
npx tsc --noEmit   # টাইপ চেক
npm run build      # প্রোডাকশন বিল্ড
```
